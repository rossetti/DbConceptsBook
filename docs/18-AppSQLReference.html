Appendix F — SQL Quick Reference

This appendix collects, in one place, the SQL this book teaches: the statements that define tables, the statements that change data, the clauses of a query, and the data types and functions the chapters use. It is a reminder, not a tutorial. Each entry names the section that teaches it, where the examples and the reasons are.

The skeletons follow three conventions. Words in upper case are SQL; words in lower case stand for names or values you supply. Square brackets enclose what may be left out, and ... means the previous item may repeat. PostgreSQL is the reference system (Section 1.3); a feature marked (PostgreSQL) is PostgreSQL’s own, not standard SQL, and may be written differently in another DBMS.

F.1 Defining tables

A table is created with its columns and its rules together. The skeleton gives the parts the book’s tables use:

CREATE TABLE schema_name.table_name (
    table_pk INTEGER GENERATED ALWAYS AS IDENTITY
        PRIMARY KEY,
    column_name type [NOT NULL] [DEFAULT value]
        [UNIQUE] [CHECK (condition)],
    other_fk INTEGER [NOT NULL]
        REFERENCES schema_name.other_table
        [ON DELETE action] [ON UPDATE action],
    ...
    [UNIQUE (column_name, ...)],
    [CHECK (condition)]
);

A table’s definition changes with ALTER TABLE, and the other statements that define things follow the same pattern:

ALTER TABLE table_name ADD COLUMN column_name type;
ALTER TABLE table_name DROP COLUMN column_name;
ALTER TABLE table_name
    ALTER COLUMN column_name SET NOT NULL;
ALTER TABLE table_name
    ADD CONSTRAINT name CHECK (condition);
ALTER TABLE table_name RENAME TO new_name;
DROP TABLE table_name [CASCADE];
DROP SCHEMA schema_name [CASCADE];

F.2 Changing data

Three statements change rows, and a fourth loads them from a file:

INSERT INTO table_name (column_name, ...)
VALUES (value, ...), ...;

INSERT INTO table_name (column_name, ...)
SELECT ...;

UPDATE table_name
SET column_name = expression, ...
[WHERE condition];

DELETE FROM table_name
[WHERE condition];

A transaction groups changes so that they happen together or not at all (Section 9.2):

BEGIN;          -- or START TRANSACTION
...             -- statements
COMMIT;         -- keep the changes, or
ROLLBACK;       -- undo them

F.3 Queries

A query’s clauses are written in one order and evaluated in another. The skeleton gives the written order; the database evaluates FROM and its joins first, then WHERE, GROUP BY, HAVING, the window functions, the SELECT list, DISTINCT, ORDER BY, and finally LIMIT. That is why a WHERE clause cannot name a column alias from the SELECT list, and why it runs before the grouping that HAVING filters.

[WITH [RECURSIVE] name AS (query), ...]
SELECT [DISTINCT] expression [AS alias], ...
FROM table [AS alias]
    [[LEFT | RIGHT | FULL] JOIN table [AS alias]
        ON condition] ...
[WHERE condition]
[GROUP BY expression, ...]
[HAVING condition]
[ORDER BY expression [ASC | DESC], ...]
[LIMIT n];

A CASE expression chooses a value by condition, and an aggregate’s FILTER restricts the rows it counts:

CASE WHEN condition THEN value
     [WHEN condition THEN value] ...
     [ELSE value]
END

A window function computes a value for each row from a window of related rows, without collapsing them into one:

function(...) OVER (
    [PARTITION BY expression, ...]
    [ORDER BY expression, ...]
    [ROWS BETWEEN n PRECEDING AND CURRENT ROW])
