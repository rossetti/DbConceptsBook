Defining Tables and Changing Data

Read the sections

Self-Check

1. The customer_order table has a check named order_ship_after_order, and the business decides to drop that rule. Which statement removes it?

DROP NOT NULL lets one column take NULL again, and it is written with ALTER COLUMN and the column’s name. It does not remove a check.

Yes. A constraint is removed by its name, which is one reason to name a constraint when you create it.

DELETE removes rows. A constraint is part of the table’s definition, which ALTER TABLE changes.

The constraint is not a column. DROP COLUMN removes a column and its values.

2. A table declares customer_fk INTEGER NOT NULL REFERENCES distribution.customer, naming no column of customer. Which column of customer does the foreign key refer to?

The position of a column has nothing to do with it.

Yes. REFERENCES table with no column list refers to the table’s primary key.

A foreign key refers to one key. Naming a UNIQUE column takes a column list.

The column list may be left out, and the primary key is then assumed.

3. A script must start a transaction in the words of the SQL standard, so that it reads the same on another DBMS. Which statement does that?

PostgreSQL accepts BEGIN, and the reference lists it, but the standard’s words are different.

Yes. START TRANSACTION begins a transaction, which COMMIT or ROLLBACK then ends.

COMMIT ends a transaction, keeping its changes.

The standard uses SET TRANSACTION to set a transaction’s isolation level, not to start one.

Queries

Read the section

Self-Check

1. An analyst combines two queries with UNION. The first selects customer_number and name; the second selects only customer_number. What happens?

The set operations do not pad a query’s columns. Each query must supply every column.

Yes. The rows of the two results are compared column by column, so the columns must line up.

The set operations match columns by position, not by name, and do not drop any.

A join pairs rows side by side; a set operation stacks or compares whole rows.

2. A report must show each order line with the total quantity of its order beside it, one row per line. How does a window function differ from GROUP BY for this?

GROUP BY collapses each group into one row. A window function does not.

Yes. SUM(quantity) OVER (PARTITION BY ...) gives each line its order’s total while the lines stay separate.

PARTITION BY alone is enough to form the windows; the ordering and the frame are optional.

HAVING filters groups formed by GROUP BY; a window function needs no HAVING.

3. A query must run on another DBMS as well as on PostgreSQL. Which of these does the reference mark as PostgreSQL’s own, to be written differently elsewhere? Select every one.

Select all that apply.

Yes. The standard’s form is FETCH FIRST 10 ROWS ONLY.

This is the standard’s form, which PostgreSQL also accepts.

Yes. ILIKE matches while ignoring case; LIKE is the standard operator.

Outer joins are standard SQL.

Yes. :: is PostgreSQL’s shorthand; the standard writes CAST(list_price AS NUMERIC(10,2)).

PostgreSQL Data Types and Functions

Read the section

Self-Check

1. A report needs one text column that reads, for example, HT-100 Two-wheel hand truck, built from product_number and description. Which expression gives it?

Yes. The operator || joins text, and the ' ' in the middle puts a space between the two values.

In PostgreSQL, + adds numbers. Text is joined with ||.

STRING_AGG joins the text values of a group of rows into one. It does not join two columns of one row.

CAST converts a value to a type, and description is a column, not a type.

2. A quality engineer wants the median of each characteristic’s measured values. Which aggregate from the reference gives it?

AVG gives the mean, which an outlying value can pull away from the middle.

Yes. The 0.5 quantile is the median, and the values must be ordered, which is why the order is written after WITHIN GROUP.

Half the largest value is not the middle of the values.

That is the sample standard deviation, a measure of spread, not of the middle.

3. A maintenance plan records how long each planned machine stop lasts, such as 3 hours and 30 minutes. Which type from the reference holds that value?

TIME holds a time of day, such as 3:30 in the morning, not a length of time.

A TIMESTAMP holds a date and a time, a moment rather than a duration.

Yes. An INTERVAL is a length of time, and it can be added to a TIMESTAMP to find when the stop ends.

Stored as text, the durations could not be added, averaged, or compared.
