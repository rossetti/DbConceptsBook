A Program’s View of a Database

Read the section

Self-Check

1. A program that uses the KSL connects to the book’s PostgreSQL database with nothing else added to its build. What part of JDBC makes that possible?

Yes. JDBC is a set of interfaces; each database system implements them with a driver, and the program needs the driver for the system it reaches.

JDBC is a standard set of interfaces. It is the driver, one per database system, that does the speaking.

PostgreSQL is a server of its own, always running. The program connects to it; it does not run it.

A program and DataGrip are separate clients of the same server. Each opens its own connection.

2. The column order_date is DATE. Which call reads it as a Kotlin LocalDate?

Yes. getObject, given the class to return, reads the date as a LocalDate, the Kotlin type that matches DATE.

getString returns the date’s text, which the program would still have to turn into a date.

A date is not a whole number; getInt reads INTEGER columns.

getBigDecimal reads exact decimal numbers, the NUMERIC columns.

3. LotMeasurements reads its rows with while (rows.next()) { ... }. It is given a lot number that no inspection has, so the query returns no rows. What happens?

Yes. rows.next() moves to the next row and returns false when there is none, here on the first call.

A result set with no rows has no row to read; the first call of rows.next() returns false.

A query that matches no rows is not an error. It returns a result set with no rows.

rows.next() does not wait; it returns false when the rows are used up.

4. The book writes every connection, prepared statement, and result set inside a use block. Which of these are reasons? Select every one that applies.

Select all that apply.

Yes. Closing releases them.

Yes. A close written by hand at the end of the block is skipped when an exception leaves the block early.

Yes. The failure shows up later, often far from the code that caused it.

Committing is the connection’s commit(), or auto-commit. use only closes.

use changes when an object is closed, not how the query runs.

Parameterized Queries and SQL Injection

Read the section

Self-Check

1. A function pastes a lot number into its SQL text, "WHERE i.lot_number = '$lotNumber'", and counts the lot’s measurements. It is given the input L7005-03' OR '1'='1. What does it count?

The quote in the input ends the SQL string early, so the rest of the input is read as SQL.

Yes. The condition becomes i.lot_number = 'L7005-03' OR '1'='1', which is true of every row. The input has changed what the query does.

That is what a parameterized query counts. Pasted into the SQL, the input is not treated as a lot number.

The quotes in this input happen to balance, so the statement is valid SQL with a different meaning.

2. A lot number with a mistyped apostrophe, L7005'03, is given to a function that supplies it with setString. The function counts 0 measurements rather than failing. Why?

Nothing is stripped. The value is compared exactly as given.

Yes. The statement was parsed before the value arrived, so no character in the value can end a string or start new SQL.

The database recognizes nothing. It simply uses the value as a value.

It does not skip the value. A customer named with an apostrophe is found by the same query.

3. A function counts the measurements of the lots inspected between two dates that a user types. Which way of writing it follows the chapter’s rule?

Yes. A value that comes from outside the program goes into SQL only as a parameter.

A check of the input is not the rule, and a check can miss a case. The value still becomes part of the SQL text.

The input is whatever the user typed; nothing makes it a date until the program treats it as a value.

Doubling quotes by hand is the repair a parameter makes unnecessary, and the value is still part of the SQL text.

4. True or False: A prepared statement prevents SQL injection by examining each value for dangerous characters, such as quotes, before sending it.

Nothing in the value is examined. The protection comes from when the value arrives, not from what it contains.

Right. The SQL, with its ?, reaches the database first and is parsed; the values follow separately, and the database uses each as a value, never as SQL, whatever characters it contains.

CRUD and the Data Access Object

Read the section

Self-Check

1. A program records inspections, reports on them, and corrects them, and its SQL is written wherever it is needed. What does moving that SQL into a data access object change?

The tables stay in the database. Only the place where the program’s SQL is written changes.

Yes. A change to the tables is made in one class, and the rest of the program reads as the business does.

The DAO is written by hand, with SQL in each of its methods. It gathers the SQL; it does not generate it.

The data classes know nothing about databases. Only the DAO sends SQL.

2. The data class Inspection names its part by partNumber and has no property for part_fk or inspection_pk. Where do those keys come from when an inspection is stored?

Then every caller would handle surrogate keys, which is what the DAO exists to hide.

Yes. Translating business keys into surrogate keys is the DAO’s real work, done at run time every time an object is stored.

A data class only holds values. It cannot know the keys the database assigned.

The inspection refers to its part and its operator by foreign keys, which must be filled.

3. The DAO’s create is given a gauge file whose second characteristic is spelled Lenght. The inspection and the diameter insert without error; the length’s insert fails. What is in the database afterward?

That is the half a lot the transaction exists to prevent.

The diameter’s insert succeeded before the failure, so it was in the same position as the inspection’s.

Yes. The catch rolls back everything the method did, so the file records all or none.

The NOT NULL foreign key refused the length’s row, and the rollback then removed the rest.

4. In the UML diagrams of the pattern, what does a dashed arrow from the program to the data access object say?

Yes. A dashed arrow is a dependency. A solid arrow is an association, a link the object keeps.

Nothing in the diagram is a subclass; the arrow shows use.

A lasting link is an association, drawn solid, like the DAO’s arrow to its Connection.

Only the DAO sends SQL. The program depends on the DAO, never on the database.

The KSL Database Utilities

Read the section

Self-Check

1. A program sets the default schema and then counts a table’s rows:

db.defaultSchemaName = "production"
println(db.numRows("measurement"))

measurement is in the quality schema. What happens?

A method given a table name alone looks only in the default schema.

Finding no table in the default schema is not an error here.

Yes. A wrong count that looks like an answer is the risk, so set defaultSchemaName to the schema you work in, or name the schema.

Only the default schema is searched.

2. A data class extends DbTableData to give one table CRUD without SQL. Which statements about it are true? Select every one that applies.

Select all that apply.

Yes. The KSL writes each property to the column of the same name.

Yes. The KSL reads a row into the properties by position.

Yes. The key the database chose is copied back, so a later update can find the row.

It is limited to what one table can do. Work across tables in one transaction needs a DAO.

It knows nothing of business keys in other tables; that is the hand-written DAO’s work.

3. DatabaseIfc.toDataFrame turns a result set into a data frame. A Statistic needs Double values, and the measured_value column is NUMERIC(10,4). Why does the program convert each value with (it as Number).toDouble()?

The frame’s columns are typed. A NUMERIC column has the type BigDecimal.

Yes. Number covers whichever numeric type the column holds, and toDouble() gives each value the type Statistic takes.

The conversion does not round; it changes the type.

The conversion concerns the values’ type, not how many there are.

4. True or False: executeCommand builds its statement safely, so it is a good way to run SQL that includes a lot number typed by a user.

executeCommand takes a finished string, like the unsafe function that pasted values into SQL.

Right. It is for fixed SQL written in the program. A value from a user goes into a prepared statement as a parameter.

Importing and Exporting Data, and Libraries That Write the SQL

Read the sections

Self-Check

1. A gauge file has a header line and then one line per measurement, with the characteristic’s name in its fifth field. A program reads it with CSVUtil.readRows(path, skipLines = 1). What is rows.first()[4]?

skipLines = 1 skips the header, so the first record is the first measurement.

Yes. The fields are read by position from 0, so [4] is the fifth field of the first line after the header.

Positions count from 0, so [4] is the fifth field.

rows.first() picks the record; [4] picks a field within it.

2. A program loads many rows with one prepared INSERT. Which statements about loading them as a batch are true? Select every one that applies.

Select all that apply.

Yes. That is the sequence of a batch.

Yes. That is the reason to batch.

executeBatch() is called once, after the last row is added, and sends them all.

The batch still uses a prepared statement with a ? for each value.

3. A program’s SQL misspells a column as measured_valu. Which approach lets the compiler find the mistake before the program runs?

The compiler checks nothing inside a string; the mistake appears when the query runs.

Names in strings are not checked either. The check comes from the code generator.

Yes. The column becomes a generated name, and a misspelled one does not compile.

PostgreSQL sees the SQL only when the program sends it, at run time.

1. A program must record a machine’s cycle together with the parts it produced, rows in three tables that belong together, and must never leave half a cycle recorded. What should do the work?

DbTableData suits one simple table. It knows nothing of transactions across tables.

Yes. The DAO knows which changes belong together, so it is the natural place for the transaction.

Each call is a separate statement on a finished string, with no transaction joining them and no parameters.

Exporting moves data out of the database, not into it.

2. Which of these send a value supplied at run time as a parameter rather than as part of the SQL text? Select every one that applies.

Select all that apply.

Yes. The SQL and the value travel separately.

Yes. Inside, the KSL builds prepared statements with a ? for each property.

Yes. The SQL jOOQ printed shows a ? where the value goes.

The template pastes the value into the SQL text, which is how injection happens.

The command is a finished string; the value is already part of the SQL.

3. A quality engineer’s program reports the capability of a turning process from the measurements in the database. Through which steps do the measurements pass?

Yes. That path, from SQL to statistics, is how a database feeds any analysis in Kotlin.

The query runs in the database; its result set becomes the data frame.

Nothing here needs to be inserted or exported. The program reads what is stored.

A batch loads rows into the database; this program only reads them.
