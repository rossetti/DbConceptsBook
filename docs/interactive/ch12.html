Input Data for Models

Read the section

Self-Check

1. The hand calculation says a work center should be busy about 80 percent of the time. The simulation, over 30 replications, reports its utilization as 0.62. What is the right next step?

A model whose utilization disagrees with its own inputs is not doing what those inputs say. Its waiting times cannot be trusted until the gap is explained.

Yes. A utilization follows from the mean arrival rate, the mean time per lot, and the number of machines, so the simulation must agree with the hand value up to random variation. A gap this large points to a mistake.

Random variation over 30 replications accounts for differences in the second or third decimal place, not a gap of 0.18.

The hand value already uses the mean of the random processing times. Randomness changes how long lots wait, not the fraction of time the work center is busy on average.

2. Two experiments of the frame line are run with the KSL’s resetStartStreamOption set, one with two welders and one with three. True or False: replication 7 of one experiment then sees the same arrivals and the same processing-time variations as replication 7 of the other.

Correct. This is common random numbers: each experiment starts from the same random numbers, so the scenarios differ only in what differs between them, here the number of welders.

Setting the option makes each experiment start from the same random numbers. Replications within one experiment still differ from each other; it is the replications with the same number in the two experiments that match.

Simulation Output Databases

Self-Check

1. The KSL stores its model elements as a nested set, with a left_count and a right_count for each. In a self-join of model_element to itself, aliased parent and child, which condition on the numbers finds every element below a given parent, at any depth?

This finds at most the first element the walk reaches after the parent. The elements below a parent are all those whose numbers lie between its own.

Yes. A depth-first walk arrives at every element below the parent after arriving at the parent and leaves it before leaving the parent. The join must also match exp_id_fk, since each experiment numbers its own tree.

This finds the elements whose numbers enclose the parent’s: the elements above it, not below.

A recursive query is needed when only the parent column is kept. The nested set numbers are what let a simple self-join find a subtree.

2. Which statements about the KSL’s output schema ksl_db are true? Select every one that is.

Select all that apply.

Yes. Each row holds one response’s statistics in one replication of one run.

Yes. A counter has only its final value in each replication, so the KSL keeps it in a table of its own. within_rep_view combines the two.

Yes. The key of model_element is the pair (exp_id_fk, element_id), and a statistic stores only element_id_fk. The database does not check that the element exists.

The parent column gives only direct children. Any depth takes the nested set numbers or a recursive query.

An experiment owns its runs and model elements, and the KSL’s foreign keys cascade: deleting the experiment deletes everything it produced.

3. An analyst wants a confidence interval for the frame line’s mean time in shop. Which values serve as the independent observations?

Lots in the same replication share its congestion: a bad month makes every lot in it slow. Pooling them treats related values as independent and makes the interval too narrow.

Yes. Each replication uses different random numbers, so the replication averages are independent observations of the same quantity, and the interval is built from them.

Every replication used different random numbers; none repeats another. All 30 are observations.

These describe the spread within one replication. The mean is estimated from the replication averages.

Analyzing Experiments with SQL

Read the section

Self-Check

1. An engineer reruns an experiment with 120 replications instead of 30, and the replication averages vary about as much as before. About how does the half-width of the 95 percent confidence interval change?

Yes. The half-width divides the standard deviation by the square root of the number of replications, and four times as many replications halve that factor. The t quantile also falls a little with more degrees of freedom.

The number of replications enters through its square root, so four times as many replications halve the half-width rather than quarter it.

The standard deviation stays about the same, but it is divided by the square root of a larger number.

More replications make the estimate of the mean more precise, never less.

2. In pw_diff_within_rep_view, experiment A is the one recorded later, ThreeWelders, and a_minus_b is its value less the value of TwoWelders. The average of a_minus_b for TimeInShop is negative. What does the sign say?

Yes. A negative difference means A’s values are the smaller: ThreeWelders has the shorter mean time in shop.

That would be a positive difference, A larger than B.

The order is fixed by which experiment was recorded later. Knowing it, the sign reads directly.

A difference is negative whenever the first value is the smaller.

3. Where does the KSL keep the average, the standard deviation, and the half-width of each response over all the replications of a run?

Yes. A row holds the summary of one response over the replications of one run.

That table holds one response’s statistics in one replication, the values a summary is computed from.

The experiment table records how the experiment was set up and run, not its results.

The KSL stores its summaries. SQL computes the summaries it did not store, and checks the ones it did.

4. Before trusting a paired comparison from pw_diff_within_rep_view, which checks are worth making? Select every one that is.

Select all that apply.

Yes. The view pairs rows by rep_id and needs equal replication counts. An experiment with a different count drops out silently, and the summary returns a count of 0 and a NULL average instead of an error.

Yes. No single column records whether the experiments shared random numbers, so these columns, and how the experiments were run, are the evidence.

If they agreed, there would be nothing to compare. Agreement of the averages says nothing about whether the pairing is sound.

The view pairs any two experiments with equal replication counts, whether or not they shared random numbers.

Designing a Database for Experimental Work

Read the section

Self-Check

1. Which statements about moving results between long and wide tables are true? Select every one that is.

Select all that apply.

Yes. Each group holds one row per variable, and each FILTER keeps the one value that belongs in its column.

Yes. Each SELECT names its variable as a constant and returns its column as the value.

The SELECTs name different variables, so they cannot produce the same row twice. UNION would only spend work looking for duplicates.

Yes. The two shapes record the same gap in different ways.

The two shapes hold the same facts. Every cell of the wide table is one row of the long table.

2. A study stores its results long: one row per replication and variable, with one column naming the variable and one value column. What does this shape give up, compared with a wide table?

Yes. A long table has one value column, so every variable shares its one type and whatever constraints the column has.

That is the long shape’s strength: grouping on the variable’s name summarizes them all at once.

Each row of a long table names its observation as well as its variable.

The two shapes hold the same facts; every cell of a wide table is one row of a long one.

3. In the data class SolverRun, bestObjective is a Double and gap a Double?. What does the CREATE TABLE statement the KSL generates from the class make of them?

Yes. A column is NOT NULL wherever the property’s Kotlin type does not allow null.

The KSL maps a type that does not allow null to a NOT NULL column.

The type of gap, Double?, allows null, and so does its column.

Every var property becomes a column, whatever its default.

2. Why does ksl_db keep simulation runs in a table of their own, apart from experiments?

Yes. Each experiment of stage K ran in one chunk, one run of 30 replications, but the design allows several.

A run holds many replications; its num_reps says how many.

Each run belongs to one experiment, through its foreign key exp_id_fk.

The stream options are columns of experiment.

3. A colleague’s model of the frame line has each work center’s setup and run minutes typed into its code. What risk does the chapter name?

Yes. A model that reads the routing from the plant’s database stays current with the plant.

Speed is not the concern. Whether the numbers still describe the plant is.

The KSL runs a model with times from anywhere. The risk is in the numbers, not in the KSL.

Common random numbers come from the stream options, not from where the times come from.
