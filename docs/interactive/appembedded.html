DuckDB

Read the section

Self-Check

1. A table of simulation results has 20 columns, and a query averages 3 of them over every row. Why does a column store such as DuckDB suit this query better than a row store?

That describes a row store, such as PostgreSQL or SQLite.

Yes. A column of like values also compresses well. A row store must pass over every column of every row it reads.

The rows are all stored; they are only arranged by column.

Finding or changing one row touches one place in a row store. That is the row store’s strength.

2. True or False: in DuckDB, a column declared VARCHAR(10) refuses a value of twelve characters.

DuckDB accepts the length in a type and ignores it, so the longer value is stored without complaint.

Right. DuckDB enforces types, but not the length in one. A length rule that matters belongs in a CHECK constraint.

3. A file of replications is long, one row per replication and response. Which statement turns it wide, one column per response, with the columns found in the data rather than listed by hand?

That works in PostgreSQL, but the query lists each response’s column by hand.

Yes. PIVOT is DuckDB’s own statement; neither PostgreSQL nor the SQL standard has it.

UNPIVOT goes the other way, from wide to long.

COPY writes a result to a file; it does not reshape it.

Self-Check

1. An analyst wants to summarize a KSL study’s results with DuckDB’s SQL, without adding DuckDB’s driver to any program. What is the usual route?

That URL needs DuckDB’s driver in the program’s build, which the KSL does not include.

Yes. DuckDB reads a CSV file where a table’s name would stand, so no program of its own is needed.

DuckDB is embedded; it reads its own files, CSV files, and Parquet files.

Querying CSV files directly is one of DuckDB’s strengths.

2. A Kotlin program opens jdbc:sqlite:stock.db. Where does the database engine run?

Yes. The program needs only the driver’s library; there is no server to reach.

SQLite has no server. The URL names a file, not a host.

DataGrip is a separate program. It can open the same file, but the program does not need it.

PostgreSQL plays no part. The driver reads and writes the file itself.
